# Roadmap

本文档整理「热量记录助手」下一阶段产品规划。优先级会随真实用户反馈、微信审核要求和识别成本表现调整。

## 已完成（v1.3.0）

- 今日营养分析：根据用户档案、当日记录和营养素进度生成个性化评价。
- 智能饮食推荐：支持将推荐餐食确认后加入今日记录。
- 私人营养顾问：支持饮食、运动和明日计划的连续对话，最近上下文仅通过云函数读取。

## P0（必须）

- 拍照识别食物
  - 支持拍摄或上传餐食图片。
  - 识别食物名称、份量、热量和三大营养素。
  - 识别结果进入现有确认页，由用户确认后保存。

- 每周/月度分析
  - 生成周报和月报。
  - 汇总热量缺口、摄入、运动、体重变化和记录连续性。
  - 给出可执行建议，而不只是展示数据。

- 体重趋势
  - 支持用户主动记录每日体重。
  - 在统计页展示体重趋势与目标体重距离。
  - 与每日记录中的体重快照保持兼容。

## P1（推荐）

- 深色模式
  - 建立暗色 Design Token。
  - 适配首页、历史页、统计页、我的页面和确认页。
  - 保持 Apple HIG 风格，避免高饱和、大面积纯黑带来的疲劳。

- 数据导出
  - 支持按日期范围导出每日记录。
  - 优先支持 CSV，后续可扩展为 Excel 或 PDF。
  - 导出字段包括食物、运动、热量、营养素、体重和汇总指标。

- 建议记录历史
  - 支持用户选择保存关键建议和执行情况。
  - 与私人营养顾问聊天记录保持清晰的隐私边界。

- 目标管理增强
  - 支持不同阶段目标：减脂、维持、增肌。
  - 支持目标周期、每周预期变化和提醒。

## P2（未来）

- Apple Health 同步（预留）
  - 预留运动、体重、能量消耗等数据映射。
  - 微信小程序环境存在平台限制，优先作为设计和数据结构预留。

- 多供应商识别服务 Provider 完整实现
  - 在现有 Provider Layer 基础上补齐更多供应商接口。
  - 支持按环境变量切换模型供应商。
  - 增加模型失败降级策略和成本监控。

- 食物库与常用餐
  - 用户可保存常吃食物和固定餐组。
  - 减少重复输入，提高记录效率。

- 社交和激励
  - 支持连续记录、目标达成徽章、轻量分享。
  - 保持克制，不做运营化打扰。
