# v1.2 Voice Input Design

## Scope

v1.2 phase one adds Mandarin voice entry to the Today composer. A recording is transcribed into editable text and then uses the existing `parseDailyInput -> confirm -> dailyRecords` flow. Photo recognition and personalized nutrition advice are explicitly out of scope for this phase.

## Existing Contracts

- Text parsing remains `parseDailyInput({ text, profile })`.
- Parsed data continues to use `foods`, `exercises`, and `summary`.
- The confirmation page remains the only place that writes a parsed result to `dailyRecords`.
- `daily_records` and `users` schemas do not change.
- No raw audio or transcript is written to a database or cloud storage.

## Architecture

The Today page owns the existing text parsing workflow. A new `daily-composer` component owns presentation and emits intent events. A focused `voiceRecorder` utility owns permission checks, `RecorderManager`, duration limits, Base64 reading, and local cleanup. A new `speechToText` cloud function validates the audio request, resolves the caller openid, calls Tencent Cloud Sentence Recognition, and returns text only.

The cloud function uses injected dependencies in its handler so request validation, error mapping, and provider behavior are testable without network access. Tencent Cloud credentials are read only from environment variables.

## Client State Machine

The supported states are:

- `idle`: text editing, microphone and submit available.
- `requestingPermission`: waiting for microphone permission.
- `recording`: timer and restrained animated level indicator visible.
- `transcribing`: recording is stopped and the cloud function is running.
- `error`: a recoverable message is shown, then the composer returns to `idle`.

Only one voice operation may be active. Navigating away, hiding the app, or unloading the page cancels recording and clears timers.

## Interaction

- A tap starts recording; a second tap ends it.
- A press held for at least 350 ms uses push-to-talk behavior; release ends it.
- Moving at least 60 px upward while holding changes the state to cancel; release discards the recording.
- Maximum product duration is 45 seconds. The recording automatically stops at the limit.
- Recordings shorter than 800 ms are rejected locally.
- The transcribed text replaces an empty composer value. If the user already has text, it is appended with Chinese punctuation.
- Transcription never starts parsing or saving automatically.

## Recording Format

Use `wx.getRecorderManager()` with MP3, 16 kHz sample rate, mono channel, 48 kbps bitrate, and a 45-second duration. The temporary MP3 is read as Base64 through `wx.getFileSystemManager()` and sent synchronously to `speechToText`.

The temporary file belongs to the WeChat runtime. After reading it, the app drops all references and attempts `unlink` when the runtime exposes a writable temporary path. Cleanup failure is ignored and never blocks text entry.

## Cloud Function Contract

Input:

```json
{
  "audioBase64": "...",
  "voiceFormat": "mp3",
  "durationMs": 12340
}
```

Success:

```json
{
  "success": true,
  "text": "今天早上吃了两个鸡蛋和一杯牛奶",
  "durationMs": 12340
}
```

Failure:

```json
{
  "success": false,
  "error": {
    "code": "TRANSCRIPTION_TIMEOUT",
    "message": "语音转写超时，请稍后重试"
  }
}
```

The handler accepts only MP3, 800-45000 ms, and a non-empty Base64 payload below 2 MB decoded size. Logs contain request IDs and error codes only, never audio, transcript, SecretId, or SecretKey.

## Tencent Cloud ASR

The provider calls SentenceRecognition with the `16k_zh` engine. Credentials come from:

- `TENCENTCLOUD_SECRET_ID`
- `TENCENTCLOUD_SECRET_KEY`
- `TENCENTCLOUD_ASR_REGION`, default `ap-shanghai`

The Node.js Tencent Cloud ASR SDK is packaged only in the `speechToText` cloud function. Provider errors are mapped to stable friendly codes; raw upstream messages are not returned to the client.

## Permission and Privacy

`app.json` declares `scope.record` with the purpose: converting spoken dietary and exercise records into editable text. Permission is requested only after the user taps the microphone. A denial shows a modal with “继续文字输入” and, when applicable, “去设置”. Text entry remains fully usable.

Before release, the WeChat privacy guide must declare microphone access and explain that voice is used for one-time transcription, is sent to Tencent Cloud ASR, and is not retained by this mini-program.

## Error Handling

- Permission denied: keep text entry active and offer settings.
- Too short: discard and show “录音时间太短，请再说一次”.
- Too long: stop at 45 seconds and continue transcription.
- Cancel: discard silently with a brief “已取消”.
- Offline/cloud failure: keep existing text and show retryable feedback.
- Timeout: reset the state and allow a new recording.
- Empty transcript: keep existing text and ask the user to try again or type.
- Page lifecycle interruption: cancel locally and do not call the cloud function.

## Verification

Automated tests cover state transitions, input merging, cloud request validation, provider invocation, friendly error mapping, secret non-disclosure, page wiring, and preservation of the original text parsing contract. Manual acceptance is required on iPhone and Android because the WeChat desktop simulator cannot validate microphone authorization and recording behavior.
